\chapter{Conclusions and Future Work}
\label{ch:conclusions}

\section{Summary of Contributions}
\label{sec:contributions}

\bluerevised{The analysis in \Cref{sec:related-tools} highlighted a gap in seismological software: no accessible tool combined 3D rendering, time animations, clustering, and structural analysis. Seismic Viewer was developed to address this need across three key areas: software architecture, data visualization, and automated analysis.}

\vspace{0.8em}
\bluerevised{\textbf{Software Architecture.} A key contribution is the dual-engine design that separates computation from presentation (\Cref{ch:architecture}). Coupling a \texttt{pywebview} \cite{pywebview} window with a local \texttt{FastAPI} \cite{fastapi} server provides desktop integration without high memory overhead, allowing the Python backend to calculate independently without freezing the interface. Additionally, the Float32 binary streaming protocol packs numerical arrays into continuous buffers, reducing payload size by $80\%$ compared to JSON and eliminating parsing delays during data transfer.}

\vspace{0.8em}
\bluerevised{\textbf{Data Visualization.} Seismic Viewer provides four display modes: 2D maps, 3D static views, 4D animated sequences, and cluster analysis workspaces. The 4D animation mode tracks how earthquake sequences evolve across time using three temporal strategies (accumulation, sliding window, and block mode), revealing migration patterns hidden in static views. Furthermore, integrating auxiliary geophysical layers (seismic tomography, ground uplift, and stations) enables direct correlation between hypocentres and subsurface structures.}

\vspace{0.8em}
\bluerevised{\textbf{Automated Structural Analysis.} The automated analytical pipeline integrates three spatial clustering algorithms: DBSCAN \cite{ester1996dbscan}, MiniBatchKMeans \cite{lloyd1982kmeans}, and cylinder grid partitioning, which prevents color changes across animation frames. Building on clustering, the system fits fault planes using RANSAC \cite{fischler1981ransac} and SVD \cite{shakarji1998least} to calculate dip, dip direction, and strike, allowing researchers to characterize fault structures interactively.}

\section{Validation and Quantitative Performance Assessment}
\label{sec:validation}

\bluerevised{The system was validated using INGV Campi Flegrei seismic datasets \cite{ingv} alongside synthetic benchmark catalogs. Testing confirmed that Seismic Viewer maintains fluid interaction and responsive frame rates on standard desktop hardware, even when rendering dense point clouds and multi-layer geophysical models.}

\subsection{Synthetic Validation of Structural Plane Extraction}

Because the true position and orientation of underground faults cannot be directly observed, the plane fitting algorithms (RANSAC and SVD) were validated using synthetic datasets where the exact geometric structures were known. These datasets were generated by mathematically defining 3D planes of points at specific strike and dip angles, and subsequently introducing random Gaussian noise and scattered outliers to simulate realistic seismic measurement errors. 

\bluerevised{As reported in \Cref{tab:bench-synthetic}, the two-stage RANSAC and SVD pipeline estimates plane orientations accurately, maintaining low angular errors for both dip and strike even under significant measurement noise and outlier contamination.}

In parallel, the global label matching algorithm (\Cref{sec:label-matching}) successfully eliminated temporal colour flickering across 4D animated cluster sequences while maintaining fast computation times, confirming its suitability for interactive exploration workflows.

\bluerevised{These angular errors are small relative to the uncertainty inherent in real earthquake catalogs. Standard hypocentral location methods typically produce positional errors in the range of 50--200~m \cite{shearer2019introduction}, which correspond to angular uncertainties of several degrees when fitting planes to shallow fault zones. The errors reported in \Cref{tab:bench-synthetic} ($<0.6^\circ$ for noise up to 100~m and 30\% outliers) therefore fall within the precision that geophysical applications require, confirming that the RANSAC and SVD pipeline is suitable for fault characterisation at the scale of local seismic swarms.}

\section{Future Research and Architectural Extensions}
\label{sec:future-work}

While Seismic Viewer achieves interactive responsiveness for current regional catalogues, several areas present opportunities for future development.

As dataset sizes continue to grow beyond the regional scale, the current Plotly.js \cite{plotlyjs} rendering pipeline may reach its practical limits. Migrating the frontend to specialised geospatial rendering engines, such as Deck.gl or a custom WebGL pipeline built on Three.js, could enable progressive level-of-detail rendering techniques. This migration would not only increase the maximum number of renderable points but also open the possibility of deploying the application as a fully browser-based web service, eliminating the need for local installation.

A second important direction concerns real-time monitoring integration. The current architecture analyses static or periodically updated catalogues, but integrating continuous data streaming protocols such as SeedLink or FDSN web services could transform the system into a live surveillance dashboard suitable for monitoring rooms. This would require extending the WebSocket communication layer to handle continuous data ingestion alongside the existing analytical pipeline.

Finally, future iterations could expand the analytical capabilities by integrating focal mechanism visualisations to represent fault kinematics directly in the 3D scene, as well as Coulomb static stress transfer maps to analyse how individual earthquakes redistribute tectonic stress across neighbouring faults.

\section{Concluding Remarks}
\label{sec:concluding}

\bluerevised{Seismic Viewer demonstrates combining web technologies with Python libraries for geophysical analysis. The architecture separating the Python backend from the WebGL frontend balanced computation speed with development speed. Python libraries (NumPy \cite{numpy2020}, scikit-learn \cite{pedregosa2011sklearn}) provide numerical routines, while the web frontend delivers 3D graphics.}

\bluerevised{The iterative workflow aligned software features with research requirements. Feedback from researchers at INGV Osservatorio Vesuviano and Roma Tre University guided features such as sub-clustering and cylinder partitioning.}

\bluerevised{This work supports the transition from static plots toward interactive exploration in seismology. By providing 4D visualization and clustering in a desktop application, Seismic Viewer offers a foundation for studying fault structures and monitoring volcanic unrest at Campi Flegrei \cite{desiena2017bradyseism, giordano2025birth}.}
