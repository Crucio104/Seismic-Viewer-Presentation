\chapter{Introduction}
\label{ch:introduction}

\section{Motivation and Context}
\label{sec:motivation}

Seismology is a data-intensive field within Earth sciences. Seismic networks continuously record events, producing datasets that describe subsurface processes such as tectonic stress and fluid movement. Interpreting earthquake data in real time is important for volcanic and seismic risk assessment.

Traditionally, earthquake catalogues have been analysed through two-dimensional maps, cross-sections, and time plots. These representations do not fully capture the spatial and temporal distribution of seismic events. An earthquake sequence moving along a fault at depth may look like a diffuse group in map view, but show a clear planar structure when examined in three dimensions and animated over time. This limitation of conventional tools motivated the development of \textbf{Seismic Viewer}.

The project was developed during an internship at the Istituto Nazionale di Geofisica e Vulcanologia (INGV). Researchers studying the Campi Flegrei area needed a tool to display spatial distributions, temporal evolution, and structural connections in an interactive desktop application.

\section{Problem Statement}
\label{sec:problem}

Despite the availability of numerous Geographic Information System (GIS) platforms and seismological software packages, a significant technological gap persists. Existing tools generally fall into one of two categories:

\begin{enumerate}[label=(\alph*)]
    \item \textbf{General-purpose GIS platforms} (e.g. QGIS, ArcGIS): \revised{These offer comprehensive geospatial analysis capabilities, but their core designs prioritise static cartographic precision and 2D map layers over dynamic, high-framerate 3D point cloud manipulation. When handling large seismic catalogues with tens of thousands of hypocentres, adapting standard desktop GIS workflows to real-time 4D exploration and interactive clustering requires custom scripting and can result in noticeable rendering latency.}

    \item \textbf{Specialised seismological software} (e.g., Seisan, GMT, ObsPy): These provide robust analytical functionality but typically produce static outputs, such as static figures for print rather than interactive explorations. The learning curve is steep, requiring command-line proficiency, and the visualisation paradigm remains fundamentally two-dimensional.
\end{enumerate}

Neither category adequately addresses the need for a tool that unifies \textit{real-time 3D rendering}, \textit{temporal animation}, \textit{machine learning-based clustering}, and \textit{structural geological analysis} within a single, accessible desktop application. Seismic Viewer was designed to fill this gap.

\section{Objectives and Scope}
\label{sec:objectives}

The primary objectives of this project are:

\begin{enumerate}
    \item \textbf{Interactive 4D Visualisation}: Develop a system capable of rendering seismic hypocentres in three spatial dimensions plus time, with smooth animations and real-time filtering.

    \item \textbf{Automated Structural Analysis}: Integrate spatial clustering algorithms (DBSCAN, K-Means) and plane fitting (RANSAC + SVD) to automatically identify seismogenic structures.

    \item \textbf{Multi-Source Data Integration}: Support ingestion from local CSV files, the INGV GOSSIP online API, seismic tomography datasets ($V_p/V_s$ velocity ratios), and Global Navigation Satellite System (GNSS) ground deformation data.

    \item \textbf{Performance at Scale}: Ensure sub-second interactive response times for large datasets, through a custom Float32 binary transfer protocol, an asynchronous communication design (bridge, HTTP REST, and WebSockets), GPU-accelerated rendering, and efficient caching strategies.

    \item \textbf{Accessible User Experience}: Provide a modern, intuitive interface that does not require programming expertise, enabling geophysicists to focus on interpretation rather than tool operation.
\end{enumerate}

This \revised{report} covers the development process of the application, from the initial design to testing and evaluation. The system was evaluated using earthquake data from the Campi Flegrei caldera. In addition to practical usability, this \revised{report} explains the software solutions used to connect Python calculations with interactive 3D web graphics. The following chapters present the domain background, the system architecture, the data processing pipeline, the algorithmic foundations, the visualisation modes, the development process, and the conclusions drawn from this work.

\section{Internship Context}
\label{sec:internship}

This work was conducted as part of a university internship. The project was developed collaboratively with Giada Alfonsi, a PhD student in geology at Roma Tre University, under the supervision of Daniele Bailo, a software engineer at the INGV.

An iterative development approach was adopted, progressively expanding the software's capabilities over the duration of the internship. Rather than following a rigid specification, each development cycle was shaped by the continuous feedback and domain expertise provided by Giada Alfonsi, Professor Guido Giordano (volcanologist and professor at Roma Tre University), researchers at the INGV Osservatorio Vesuviano, and Daniele Bailo. The primary phases of the project were as follows:

\begin{itemize}
    \item \textbf{Phase 1}: Initial prototype, basic 3D visualisation, and local CSV ingestion.
    \item \textbf{Phase 2}: Implementation of K-Means clustering and connection with the web view bridge.
    \item \textbf{Phase 3}: Redesign of the user interface and integration of the INGV GOSSIP API for data import.
    \item \textbf{Phase 4}: Optimisation using binary data transfer, cylinder partitioning, sub-clustering, and automatic tuning of DBSCAN parameters with K-distance analysis.
    \item \textbf{Phase 5}: Integration of seismic tomography, ground uplift layers, and monitoring station positions.
    \item \textbf{Phase 6}: Modular refactoring of the package, setup of FastAPI and WebSockets, and automated tests.
\end{itemize}

This collaborative and iterative feedback process proved essential for aligning the software with real analytical workflows, as several key features (such as the cylinder grid partitioning and the sub-clustering interface) emerged directly from practical requirements and discussions during development.
