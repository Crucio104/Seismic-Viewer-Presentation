\chapter{Visualisation Modes}
\label{ch:visualisation}

Seismic Viewer provides four primary visualisation modes, each addressing a distinct analytical need. This chapter documents their implementation, rendering strategies, and integration with auxiliary geophysical data layers.

\section{2D Geospatial Map View}
\label{sec:view-2d}

The 2D view provides a plan-view representation of earthquake epicentres overlaid on OpenStreetMap \cite{openstreetmap} tiles, implemented through Plotly's \texttt{scatter\_mapbox} trace type. The map visualises seismic data using two distinct graphical layers:
\begin{itemize}
    \item \textbf{Scatter Markers}: Each earthquake is represented by a circular marker. The visual properties of these circles can be mapped to different physical parameters depending on the analytical needs. By default, the size of the circle indicates the magnitude of the event (with a minimum size threshold to ensure extremely weak micro-earthquakes remain visible), and the color represents the hypocentral depth. However, these mappings are highly flexible, allowing users to visualize other variables, such as chronological progression. Users can interact with these markers by hovering over them to reveal detailed statistics.
    \item \textbf{Density Heatmap}: A spatial density layer that visually aggregates tightly clustered earthquakes. By rendering a continuous color gradient over regions of high seismicity, this optional overlay allows researchers to intuitively identify active swarm locations and broader structural trends that might be difficult to perceive when analyzing individual scatter points alone.
\end{itemize}

To explore the dataset, users can apply filters based on magnitude, depth, and date ranges using dedicated input fields located on the left-hand panel. All filtering operations are processed directly within the user's web browser. This approach avoids sending new requests to the main server, guaranteeing that the map updates instantly whenever a parameter is changed.

\section{3D Static View}
\label{sec:view-3d-static}

The 3D static view renders hypocentres as a subsurface point cloud within a three-dimensional geographic volume beneath an OpenStreetMap terrain surface. The reference terrain is rendered as a flat, unshaded map layer for clarity, while earthquakes are represented beneath the surface as a 3D point cloud, colour-coded by variables like depth or time.

To prevent geographic distortion caused by Earth's sphericity, the system scales horizontal proportions based on latitude:
\begin{equation}
    \text{ratio}_x = \frac{\Delta\lambda \cdot K \cdot \cos(\bar{\phi})}{\max(d_\text{lon}, d_\text{lat})}, \quad
    \text{ratio}_y = \frac{\Delta\phi \cdot K}{\max(d_\text{lon}, d_\text{lat})}
    \label{eq:aspect-ratio}
\end{equation}
where $\Delta\lambda$ and $\Delta\phi$ are the longitude and latitude spans, $K = 111.32$~km/° is the equatorial conversion factor, and $\bar{\phi}$ is the mean latitude. This adjustment preserves accurate spatial proportions.

\bluerevised{Rendering large point clouds simultaneously relies on GPU acceleration. Plotly.js uses WebGL to draw points via the \texttt{scatter3d} trace type. To maintain smooth interactive frame rates, the application applies three measures: (1) map background images are scaled to save memory, (2) automatic bounding box recalculations are disabled during updates, and (3) markers are drawn as point sprites facing the camera rather than complex 3D shapes.}

The 3D workspace (\Cref{fig:3d-multi}) enables visualization of earthquake cluster geometries. Integrating a 3D tomography model (\Cref{fig:3d-viz-tomo}) correlates seismicity with geological structures, while vertical uplift columns (\Cref{fig:3d-viz-uplift}) allow direct comparison between surface deformation and underlying seismic activity.

\section{3D Animated View (4D Visualisation)}
\label{sec:view-animated}

The animated view adds time as a fourth dimension to observe the spatio-temporal evolution of seismic sequences.

The 4D visualisation engine offers three temporal modes to analyse seismic evolution: \textbf{Accumulation} (showing all events up to the current frame), \textbf{Sliding window} (displaying events within a moving time frame), and \textbf{Block mode} (rendering discrete, non-overlapping time intervals). To ensure smooth playback and avoid memory overload, the system precomputes temporal indices and updates the 3D scene dynamically without reloading the entire figure.

\bluerevised{During 4D animations, the camera angle and zoom level must remain stable across updates. By default, Plotly reinitializes the view on coordinate changes. Setting \texttt{uirevision='constant'} in the layout preserves camera position and orientation across frames, allowing continuous interaction during playback.}

\section{3D Cluster Analysis View}
\label{sec:view-cluster}

The cluster analysis mode integrates spatial machine learning with structural geological modeling.

\subsection{Cluster Visualisation and Interactive Tuning}

To provide a comprehensive geometrical understanding of seismogenic structures, Seismic Viewer renders every identified cluster through four complementary representations within the 3D WebGL scene. These representations were chosen to address different analytical needs: boundary delineation, volumetric extent, structural orientation, and individual event membership. Together, they allow researchers to examine a cluster from multiple geometric perspectives simultaneously.
\begin{enumerate}
    \item \textbf{Wireframe Convex Hulls (\texttt{Scatter3d})}: Outer boundary envelopes highlighting the spatial footprint and volumetric extent of each distinct cluster.
    \item \textbf{Triangulated Solid Meshes} (\texttt{Mesh3d}, \texttt{alphahull=0}): Smooth, semi-transparent volumetric convex hulls enclosing the clusters.
    \item \textbf{Structural Fault Planes (\texttt{Mesh3d})}: Planar surfaces calculated via RANSAC robust estimation coupled with Singular Value Decomposition (SVD) refinement. Each plane displays orientation vectors alongside precise geological strike and dip angles upon mouse hover.
    \item \textbf{Clustered Event Spheres}: Discrete event spheres colored by cluster label using categorical palettes, with unclustered background noise explicitly assigned neutral grey.
\end{enumerate}
When users interactively adjust spatial clustering hyperparameters, such as neighborhood radius $\varepsilon$, minimum samples threshold \texttt{min\_samples}, or cluster count $K$, via the side control panel, the frontend dispatches a \texttt{get\_cluster\_update} WebSocket message. The Python backend asynchronously recomputes cluster labels and structural planes without blocking the event loop, returning the newly generated Plotly trace definitions. The frontend then replaces the existing traces in the WebGL scene, thereby updating the visualization while preserving the user's current camera perspective.

\subsection{Sub-Clustering}
\label{sec:sub-clustering}

To analyze hierarchical structures, researchers can perform secondary sub-clustering on specific data subsets. By utilizing the \textbf{locked clusters} feature, users can preserve previously identified and validated groups. The algorithm will then selectively re-analyze and sub-divide all the remaining unlocked clusters simultaneously. The refined results can subsequently be applied back to merge cleanly into the parent view.

\Cref{fig:cluster-multi} provides a comprehensive overview of the clustering tools. \Cref{fig:cluster-viz} shows the standard 3D clustering interface. \Cref{fig:anim-clustering-noplanes} displays how clustering evolves over time. To ensure visual consistency, a tracking algorithm guarantees that each cluster maintains the same color across all animation frames. Finally, \Cref{fig:anim-clustering-planes} and \Cref{fig:anim-clustering-unified} combine the animated clusters with dynamically calculated fault planes and spatial cylinders. This combination allows researchers to easily observe how geological structures evolve and rotate over time.

\section{Additional Data Layers \& View Caching}
\label{sec:additional-layers}

\subsection{Auxiliary Layers: Tomography, Uplift, and Stations}
\label{sec:tomography}
\label{sec:uplift}
\label{sec:stations}

Seismic Viewer integrates three auxiliary data types processed via \texttt{core/}\allowbreak\texttt{layer\_utils.py}:
\begin{itemize}
    \item \textbf{Seismic Tomography ($V_p/V_s$ Ratio)}: The raw tomographic data, originally provided in UTM Zone~33N coordinates, is converted to geographic coordinates and mapped onto a regular 3D grid. Because measurements only exist at specific surveyed points, the software must estimate the values for the surrounding empty space. It achieves this using \textit{Inverse Distance Weighting}, a spatial interpolation technique. The value of any unknown point is calculated as a weighted average of its $k=16$ nearest known neighbors. The closer a neighbor is, the stronger its influence on the final calculation, scaling inversely with the square of the distance ($p=2$):
    \begin{equation}
        V(\mathbf{x}) = \frac{\sum_{i=1}^{k} w_i \cdot V_i}{\sum_{i=1}^{k} w_i}, \quad w_i = \frac{1}{d(\mathbf{x}, \mathbf{x}_i)^2}
        \label{eq:idw}
    \end{equation}
    However, Inverse Distance Weighting can produce unrealistic mathematical artifacts in empty regions located very far from actual measurement stations. To solve this, the system applies a \textit{distance-decay} function, which acts as a spatial fade-out effect. As the distance from the nearest station increases, this function smoothly blends the estimated value back into the standard natural background value of the Earth's crust ($1.75$):
    \begin{equation}
        V_\text{final}(\mathbf{x}) = \alpha(\mathbf{x}) \cdot V_\text{IDW}(\mathbf{x}) + (1 - \alpha(\mathbf{x})) \cdot 1.75
        \label{eq:gaussian-damping}
    \end{equation}
    where $\alpha(\mathbf{x}) = \exp(-(d_\text{min}/\sigma)^2)$ with $\sigma = 0.15$ acts as the blending weight, decreasing smoothly from 1 (near known data) to 0 (far away). The value $\sigma = 0.15$~degrees (${\approx}17$~km) was chosen to match the typical distance between survey stations in the Campi Flegrei dataset, so that the fade-out occurs at the same scale as the station spacing.
    \item \textbf{GNSS Ground Deformation (Uplift)}: To visualize ground movement, the system reads historical displacement records and matches them with the known locations of the monitoring stations. This provides the exact vertical movement at any given time. Because data is only available at these specific points, the software estimates the ground movement in the empty areas between them using the same distance-based averaging (IDW) described above. The final result is displayed on the map either as a colored 2D grid or as 3D columns rising from the surface.
    \item \textbf{Monitoring Stations}: Permanent station positions are plotted as labelled markers, aiding spatial evaluation of catalogue completeness thresholds.
\end{itemize}

These three auxiliary layers serve complementary roles in the interpretation workflow. By overlaying tomographic anomalies and ground deformation patterns onto the same 3D scene as the earthquake hypocentres, researchers can visually assess whether seismic swarms correlate with known velocity anomalies or with areas of maximum surface uplift, providing a more integrated understanding of the underlying volcanic processes.

\subsection{View Caching and Navigation}
\label{sec:view-caching}

To ensure faster navigation between complex workspaces, the backend bridge maintains an in-memory view cache (\texttt{\_html\_store}, max 15 entries) keyed by a composite tuple of file path, view style, animation/windowing parameters, clustering configuration, and locked cluster states. A navigation history stack (\texttt{\_history\_stack}) allows instantaneous back and forward navigation in the clustering view while preserving exact parameter context.
